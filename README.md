# envguard

> Profile-aware, type-safe settings and secrets management built on
> [`pydantic-settings`](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).

`envguard` adds the pieces most apps keep re-implementing on top of
`pydantic-settings`:

- **Profiles** — `dev` / `staging` / `prod` (or anything you want) select which
  `.env` files get loaded, with clear precedence.
- **Secret detection & masking** — secrets are spotted automatically (by field
  type, name, or an explicit marker) and redacted from logs and `repr`.
- **Actionable errors** — missing or invalid keys produce a readable report with
  the exact environment variable names instead of a raw pydantic traceback.
- **CLI** — generate a `.env.example` straight from your settings models and
  validate the current environment before your app starts.

## Installation

```bash
pip install envguard
# or
uv add envguard
```

Requires Python 3.10+.

## Quick start

```python
from pydantic import Field, SecretStr
from envguard import EnvGuardBaseSettings


class Settings(EnvGuardBaseSettings):
    environment: str = "dev"
    database_url: str = Field(description="PostgreSQL connection string")
    api_secret: SecretStr = Field(description="Secret used to sign API tokens")
    debug: bool = False


settings = Settings()
print(settings)  # api_secret is masked in the repr
```

`Settings` reads values from (highest precedence first):

1. explicit keyword arguments — `Settings(database_url="...")`
2. environment variables — `DATABASE_URL`, `API_SECRET`, ...
3. profile-aware `.env` files (see below)

Type validation, defaults, and nested models are all handled by
`pydantic-settings` (`SOME__NESTED__KEY` maps to `some.nested.key`).

## Profiles

The active profile is resolved from the `ENVGUARD_PROFILE` (or `ENV_PROFILE`)
environment variable, defaulting to `dev`. Files are loaded from lowest to
highest precedence:

```
.env                    # shared defaults
.env.<profile>          # profile overrides
.env.<profile>.local    # local overrides (git-ignored)
```

```bash
ENVGUARD_PROFILE=prod python app.py
```

```python
from envguard import get_profile, get_env_files

get_profile()            # "prod"
get_env_files()          # (Path('.env'), Path('.env.prod'))
```

## Secrets & masking

A field is treated as a secret when **any** of these is true:

- its type is `SecretStr` (or contains it, e.g. `SecretStr | None`);
- its name contains a hint such as `secret`, `password`, `token`, `api_key`,
  `private_key`, `dsn`, `credential`, or `auth`;
- it is explicitly marked: `Field(json_schema_extra={"secret": True})`.

Secret values are automatically registered for log redaction and masked in the
model's `repr`:

```python
from envguard import install_logging_filter, mask, redact

install_logging_filter()   # attach the redaction filter to the root logger
mask("hunter2")            # "********"
mask("abcdef", reveal=2)   # "********ef"
```

```python
import logging

from envguard import EnvGuardBaseSettings, install_logging_filter
from pydantic import SecretStr

install_logging_filter()


class Settings(EnvGuardBaseSettings):
    api_secret: SecretStr


settings = Settings(api_secret="super-secret")
logging.info("using token %s", settings.api_secret.get_secret_value())
# -> using token ***
```

## Clear error messages

When required keys are missing, `envguard` raises `MissingEnvError` instead of a
raw pydantic error:

```
Cannot load Settings (profile 'dev'):

  Missing 2 required setting(s):
    - DATABASE_URL: Field required
    - API_SECRET: Field required

  Set these in your .env file or as environment variables.
  Tip: run `envguard example --model app_settings:Settings` to generate a .env.example.
```

`MissingEnvError.missing` and `MissingEnvError.invalid` map environment variable
names to validation messages.

## CLI

### Generate `.env.example` from your models

```bash
envguard example --model app_settings:Settings --output .env.example
```

Options:

| Flag                 | Description                                        |
| -------------------- | -------------------------------------------------- |
| `--model`            | Import path `module:ClassName` (required).         |
| `--output`           | Output path (default: `.env.example`).              |
| `--profile`          | Profile name (default: env or `dev`).               |
| `--include-optional` | Also emit optional fields with their defaults.     |
| `--force`            | Overwrite the output file if it exists.            |

Sample output:

```dotenv
# Generated by envguard. Do not commit real secrets.
# Profile: dev
# Model: app_settings:Settings

# PostgreSQL connection string [required]
DATABASE_URL=
# Secret used to sign API tokens [required, secret]
API_SECRET=changeme
```

### Validate the environment

```bash
envguard check --model app_settings:Settings
# OK: Settings validated (profile 'dev')      # exit code 0
# ... friendly report ...                     # exit code 1 if invalid
```

## نظرة عامة بالعربية

`envguard` مكتبة لإدارة الإعدادات والأسرار مبنية على `pydantic-settings`، تضيف:

- **Profiles** عبر متغير البيئة `ENVGUARD_PROFILE` مع تحميل `.env` ثم
  `.env.<profile>` ثم `.env.<profile>.local`.
- **تعتيم الأسرار** تلقائيًا في اللوجز و`repr` حسب النوع أو الاسم أو علامة صريحة.
- **رسائل أخطاء واضحة** للمفاتيح المفقودة أو غير الصحيحة بأسماء متغيرات البيئة.
- **واجهة أوامر**:

```bash
# توليد ملف .env.example من الموديل
envguard example --model app_settings:Settings

# التحقق من صحة الإعدادات الحالية
envguard check --model app_settings:Settings
```

مثال الاستخدام:

```python
from pydantic import SecretStr
from envguard import EnvGuardBaseSettings


class Settings(EnvGuardBaseSettings):
    database_url: str
    api_secret: SecretStr


settings = Settings()
```
